Exercise 1 - Dot-Product Attention

You are given a set of encoder annotation vectors \[ \mathbf{h}_1 = (1,2,3)^\top,\quad \mathbf{h}_2 = (1,2,1)^\top,\quad \mathbf{h}_3 = (0,1,-1)^\top \] and a decoder state (the alignment source vector) \(\mathbf{s}=(1,2,1)^\top\).

(a) Compute the resulting dot-product attention weights \(\alpha_i\) for \(i=1,2,3\) and the resulting context vector \(\mathbf{c} = \sum_i \alpha_i \mathbf{h}_i\).

(b) Compare \(\mathbf{c}\) with the context vector obtained by average pooling the \(\mathbf{h}_i\). Why is attention called “content-based addressing”?

Solution

(a) The scores are \(\mathbf{s}^\top\mathbf{h}_1 = 1 + 4 + 3 = 8\), \(\mathbf{s}^\top\mathbf{h}_2 = 1 + 4 + 1 = 6\), and \(\mathbf{s}^\top\mathbf{h}_3 = 0 + 2 - 1 = 1\). Applying softmax: \[ \boldsymbol{\alpha} = \text{softmax}\begin{pmatrix} 8 \\ 6 \\ 1 \end{pmatrix} \approx \begin{pmatrix} 0.880 \\ 0.119 \\ 0.001 \end{pmatrix}. \] The context vector is the weighted sum of the \(\mathbf{h}_i\): \[ \mathbf{c} = \alpha_1 \mathbf{h}_1 + \alpha_2 \mathbf{h}_2 + \alpha_3 \mathbf{h}_3 \approx (1.00,\; 2.00,\; 2.76)^\top. \] A simple implementation:

import torch
h = torch.tensor([[1., 2., 3.], [1., 2., 1.], [0., 1., -1.]])   # rows are h_i
s = torch.tensor([1., 2., 1.])
alpha = torch.softmax(h @ s, dim=0)
c = alpha @ h
print(alpha, c)

(b) Average pooling gives \(\frac{1}{3}(\mathbf{h}_1 + \mathbf{h}_2 + \mathbf{h}_3) = (0.67, 1.67, 1.00)^\top\), regardless of the decoder state. Attention instead weights each annotation by how well its content matches the query \(\mathbf{s}\), so a different decoder state retrieves a different mixture of the annotations. Which annotations are retrieved depends on their content, not on their position in the sequence.

Exercise 2 - Scaled Dot-Product Attention in Transformers

Transformers use a scaled dot-product attention mechanism given by \[ C = \text{attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V, \] where \(Q\in\R^{n_q\times d_k}\), \(K\in\R^{n_k\times d_k}\), \(V\in\R^{n_k\times d_v}\).

(a) Is the softmax function applied row-wise or column-wise? What is the shape of the result \(C\)?

(b) What is the value of \(d\)? Why is it needed?

(c) What is the computational complexity of this attention mechanism? How many additions and multiplications are required? Assume canonical matrix multiplication, and do not count \(\exp(x)\) towards the computational cost.

(d) In the masked (causal) variant used in decoders, a masking matrix is added before the softmax function is applied. What are its values and its shape? For simplicity, assume \(n_q=n_k = n\).

Solution

(a) \(QK^\top\) has shape \(n_q\times n_k\): row \(i\) contains the scores of query \(i\) against all keys. We need the attention weights of each query to sum to one over the keys, so the softmax is applied row-wise. The result \(C\) has shape \(n_q \times d_v\): one context vector per query.

(b) \(d = d_k\), the dimension of the queries and keys. Without the scaling, the dot products grow in magnitude with \(d_k\) (see Exercise 4), which pushes the softmax into a saturated regime where one weight is close to 1 and the gradients with respect to the scores are close to 0.

(c) Looking at each operation individually:

  • \(QK^\top\) requires \(n_q n_k d_k\) multiplications and \(n_q n_k(d_k-1)\) additions.
  • Dividing by \(\sqrt{d_k}\) requires \(n_q n_k\) divisions.
  • The softmax requires \(n_q n_k\) exponentials, \(n_q(n_k-1)\) additions, and \(n_q n_k\) divisions.
  • The final matrix multiplication requires \(n_q n_k d_v\) multiplications and \(n_q d_v (n_k-1)\) additions.

Overall, the cost is \(O(n_q n_k (d_k + d_v))\). For self-attention over a sequence of length \(n\), this is quadratic in \(n\).

(d) The mask is an \(n \times n\) matrix \(M\) with \(M_{ij} = 0\) for \(j \leq i\) and \(M_{ij} = -\infty\) for \(j > i\) (i.e. \(-\infty\) strictly above the diagonal). After adding it to the scores, \(\exp(-\infty) = 0\), so query \(i\) assigns zero weight to all future positions \(j > i\). This prevents the decoder from “looking ahead” at tokens it is supposed to predict.

Exercise 3 - Scaled Dot-Product Attention by Hand

Consider the matrices \(Q\), \(K\), \(V\) given by \[ Q = \begin{pmatrix} 1 & 2\\ 3 & 1 \end{pmatrix},\quad K = \begin{pmatrix} 2 & 1\\ 1 & 1\\ 0 & 1 \end{pmatrix},\quad V=\begin{pmatrix} 1 & 2 & -2\\ 1 & 1 & 2 \\ 0 & 1 & -1 \end{pmatrix}. \] Compute the context matrix \(C\) using scaled dot-product attention.

Solution

Here \(d_k = 2\). The scores and attention weights are \[ QK^\top = \begin{pmatrix} 4 & 3 & 2 \\ 7 & 4 & 1 \end{pmatrix}, \qquad \text{softmax}\left(\frac{QK^\top}{\sqrt{2}}\right) \approx \begin{pmatrix} 0.576 & 0.284 & 0.140 \\ 0.882 & 0.106 & 0.013 \end{pmatrix}. \] The resulting context matrix is \[ C\approx \begin{pmatrix} 0.86 & 1.58 & -0.72\\ 0.99 & 1.88 & -1.56 \end{pmatrix}. \] A simple implementation:

import torch
Q = torch.tensor([[1, 2], [3, 1]]).float()
K = torch.tensor([[2, 1], [1, 1], [0, 1]]).float()
V = torch.tensor([[1, 2, -2], [1, 1, 2], [0, 1, -1]]).float()
d_k = K.shape[1]
S = torch.softmax(Q @ K.T / d_k ** 0.5, dim=1)
print(S @ V)

PyTorch also provides a function for scaled dot-product attention:

import torch.nn.functional as F
F.scaled_dot_product_attention(Q, K, V)

Exercise 4 - Why Scale by \(\sqrt{d_k}\)?

Let \(\mathbf{q}, \mathbf{k} \in \R^{d_k}\) be random vectors whose entries are all independent, with mean \(0\) and variance \(1\).

(a) Compute the mean and variance of the dot product \(\mathbf{q}^\top\mathbf{k}\).

(b) What are the mean and variance of \(\mathbf{q}^\top\mathbf{k} / \sqrt{d_k}\)?

(c) Explain what would happen to the softmax over scores with a large \(d_k\) (e.g. \(d_k = 512\)) without the scaling.

Solution

(a) \(\mathbf{q}^\top\mathbf{k} = \sum_{i=1}^{d_k} q_i k_i\). Each term has mean \(\E[q_i]\,\E[k_i] = 0\) and variance \(\E[q_i^2 k_i^2] - 0 = \E[q_i^2]\,\E[k_i^2] = 1\). The terms are independent, so the sum has mean \(0\) and variance \(d_k\) (using Week 6, Exercise 1).

(b) Dividing by \(\sqrt{d_k}\) divides the variance by \(d_k\), so the scaled score has mean \(0\) and variance \(1\), independent of \(d_k\).

(c) Without scaling, the scores have standard deviation \(\sqrt{512} \approx 22.6\). Differences of tens between scores make the softmax essentially one-hot (e.g. \(e^{20} \approx 5 \times 10^8\)). In this regime, the softmax is saturated, and its derivatives with respect to the scores are nearly zero, so the attention weights barely learn.

Exercise 5 - Self-Attention Has No Notion of Order

In self-attention, the queries, keys, and values are all computed from the same input sequence \(X \in \R^{n \times d}\) (one row per token): \(Q = XW_Q\), \(K = XW_K\), \(V = XW_V\).

(a) Let \(P\) be an \(n\times n\) permutation matrix, so that \(PX\) reorders the tokens. Show that \(\text{attention}(PXW_Q, PXW_K, PXW_V) = P\cdot\text{attention}(XW_Q, XW_K, XW_V)\). Hint: \(P^\top P = I\), and applying a row-wise softmax to \(PAP^\top\) gives \(P\,\text{softmax}(A)\,P^\top\).

(b) What does this imply for a language model built only from self-attention layers, and how do Transformers fix this?

Solution

(a) The scores become \((PXW_Q)(PXW_K)^\top = P\,(XW_QW_K^\top X^\top)\,P^\top = PAP^\top\), where \(A\) is the original score matrix (including the \(1/\sqrt{d_k}\) scaling). Permuting rows and columns in the same way commutes with the row-wise softmax, so the attention weights become \(P\,\text{softmax}(A)\,P^\top\). Multiplying by the values \(PXW_V\) gives \[P\,\text{softmax}(A)\,P^\top P\,XW_V = P\,\text{softmax}(A)\,XW_V = P \cdot \text{attention}(XW_Q, XW_K, XW_V).\] So permuting the input tokens simply permutes the outputs in the same way (self-attention is permutation equivariant).

(b) Without additional information, the model cannot distinguish “dog bites man” from “man bites dog”: each token’s output depends on the set of other tokens, not their order. Transformers fix this by adding positional encodings (fixed sinusoidal vectors or learned position embeddings) to the token embeddings before the first layer, so that the representation of each token also encodes its position.

Exercise 6 - RNNs vs. Self-Attention

Consider processing a sequence of length \(t\) with hidden/embedding dimension \(k\), either with a single-layer RNN or with a single self-attention layer.

(a) For each, what is the number of sequential operations (operations that cannot be run in parallel)? What is the maximum path length between the first input and the last output?

(b) Why does a shorter path length make learning long-range dependencies easier?

(c) What is the main computational disadvantage of self-attention for very long sequences?

Solution

(a) An RNN must compute \(h^{(1)}, h^{(2)}, \ldots, h^{(t)}\) one after the other, so it needs \(O(t)\) sequential operations, and information from the first input must pass through \(O(t)\) steps to reach the last output. Self-attention computes all outputs at once from all inputs: \(O(1)\) sequential operations (a few matrix multiplications that parallelize well on GPUs) and a path length of \(O(1)\), since every output attends directly to every input.

(b) Gradients between two positions are products of Jacobians along the path connecting them. Long paths lead to vanishing or exploding gradients (Week 8). With a constant path length, the gradient signal from a distant token does not have to pass through many multiplications.

(c) Self-attention compares every position with every other position, so its time and memory cost is \(O(t^2 k)\), compared to \(O(t k^2)\) for an RNN. For long sequences (large \(t\)), the quadratic dependence on \(t\) becomes the bottleneck.

(a)-(c) One possible implementation:

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.d_k = n_heads, d_model // n_heads
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)

    def split_heads(self, x):                       # (B, n, d_model) -> (B, h, n, d_k)
        B, n, _ = x.shape
        return x.view(B, n, self.h, self.d_k).transpose(1, 2)

    def forward(self, x_q, x_kv, mask=None):
        Q = self.split_heads(self.W_q(x_q))         # (B, h, n_q, d_k)
        K = self.split_heads(self.W_k(x_kv))        # (B, h, n_k, d_k)
        V = self.split_heads(self.W_v(x_kv))        # (B, h, n_k, d_k)
        scores = Q @ K.transpose(-2, -1) / self.d_k ** 0.5   # (B, h, n_q, n_k)
        if mask is not None:
            scores = scores + mask                  # mask: (n_q, n_k), 0 or -inf
        C = torch.softmax(scores, dim=-1) @ V       # (B, h, n_q, d_k)
        B, _, n_q, _ = C.shape
        C = C.transpose(1, 2).reshape(B, n_q, self.h * self.d_k)  # concatenate heads
        return self.W_o(C)

def causal_mask(n):
    return torch.triu(torch.full((n, n), float("-inf")), diagonal=1)

class Block(nn.Module):
    def __init__(self, d_model, n_heads, d_ff):
        super().__init__()
        self.attn = MultiHeadAttention(d_model, n_heads)
        self.ffn = nn.Sequential(nn.Linear(d_model, d_ff), nn.ReLU(), nn.Linear(d_ff, d_model))
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x, mask=None):
        a = self.norm1(x + self.attn(x, x, mask))   # self-attention, Add & Norm
        return self.norm2(a + self.ffn(a))          # FFN, Add & Norm

class DecoderOnlyLM(nn.Module):
    def __init__(self, vocab_size, max_len, d_model=64, n_heads=4, d_ff=128, n_layers=2):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_len, d_model)
        self.blocks = nn.ModuleList([Block(d_model, n_heads, d_ff) for _ in range(n_layers)])
        self.out = nn.Linear(d_model, vocab_size)

    def forward(self, idx, use_mask=True):          # idx: (B, n) token indices
        n = idx.shape[1]
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(n))
        mask = causal_mask(n) if use_mask else None
        for block in self.blocks:
            x = block(x, mask)
        return self.out(x)                          # (B, n, vocab_size)

The use_mask argument is only there for part (e).

(d) Every position in a window is trained to predict the next character at once. This is teacher forcing: the model always sees the true previous characters, never its own predictions.

def train(use_mask=True, steps=500):
    torch.manual_seed(0)
    model = DecoderOnlyLM(len(chars), block_size)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    for step in range(steps):
        x, y = get_batch()
        logits = model(x, use_mask)
        loss = F.cross_entropy(logits.reshape(-1, len(chars)), y.reshape(-1))
        opt.zero_grad()
        loss.backward()
        opt.step()
        if step % 100 == 0 or step == steps - 1:
            print(f"step {step:3d}  loss {loss.item():.4f}")
    return model

@torch.no_grad()
def generate(model, prompt, n_new=60, use_mask=True):
    idx = torch.tensor([[stoi[c] for c in prompt]])
    for _ in range(n_new):
        logits = model(idx[:, -block_size:], use_mask)   # at most block_size tokens of context
        next_id = logits[0, -1].argmax()                 # most likely next character
        idx = torch.cat([idx, next_id.view(1, 1)], dim=1)
    return "".join(chars[i] for i in idx[0])

model = train()
print(generate(model, "the quick"))

Exercise 8 - Coding an Encoder-Only Transformer

Encoder-only Transformers such as BERT use unmasked self-attention, so that every token sees the whole sequence. To classify a sequence, they prepend a special [CLS] token and put a classifier on top of its final representation.

  • if use_pos is true, add learned position embeddings to all n + 1 positions;
  • apply n_layers blocks without a mask;
  • return 2 logits computed by a linear layer from the final [CLS] vector.

(b) Train the model to decide whether a sequence of 8 digits is sorted. Only about 0.02% of random digit sequences are sorted, so the function below builds a balanced dataset: each positive is a sorted random sequence, and each negative is a shuffle of random digits that is not sorted. Use Adam with learning rate 1e-3, batches of 64, and 1000 steps, and report the accuracy on 2000 fresh test sequences.

def make_batch(batch_size, n=8):
    x = torch.randint(10, (batch_size, n))
    y = torch.randint(2, (batch_size,))              # 1 = sorted, 0 = not sorted
    for i in range(batch_size):
        if y[i] == 1:
            x[i] = x[i].sort().values
        else:
            while (x[i][1:] >= x[i][:-1]).all():     # redraw until not sorted
                if (x[i] == x[i][0]).all():          # all digits equal: every order is sorted
                    x[i] = torch.randint(10, (n,))
                else:
                    x[i] = x[i][torch.randperm(n)]
    return x, y

(a)

class EncoderClassifier(nn.Module):
    def __init__(self, vocab_size=10, max_len=8, d_model=64, n_heads=4, d_ff=128,
                 n_layers=2, use_pos=True):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.cls = nn.Parameter(torch.randn(1, 1, d_model))
        self.pos_emb = nn.Embedding(max_len + 1, d_model) if use_pos else None
        self.blocks = nn.ModuleList([Block(d_model, n_heads, d_ff) for _ in range(n_layers)])
        self.head = nn.Linear(d_model, 2)

    def forward(self, idx):                           # idx: (B, n)
        B, n = idx.shape
        x = torch.cat([self.cls.expand(B, 1, -1), self.tok_emb(idx)], dim=1)  # (B, n+1, d)
        if self.pos_emb is not None:
            x = x + self.pos_emb(torch.arange(n + 1))
        for block in self.blocks:
            x = block(x)                              # no mask: every token sees every token
        return self.head(x[:, 0])                     # logits from the [CLS] position

(b)

def train(use_pos=True, steps=1000):
    torch.manual_seed(0)
    model = EncoderClassifier(use_pos=use_pos)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    for step in range(steps):
        x, y = make_batch(64)
        loss = F.cross_entropy(model(x), y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    x_test, y_test = make_batch(2000)
    with torch.no_grad():
        acc = (model(x_test).argmax(dim=1) == y_test).float().mean()
    print(f"use_pos={use_pos}: final loss {loss.item():.4f}, test accuracy {acc:.3f}")
    return model

Without position embeddings, the model does no better than chance, and the loss stays at \(\log 2 \approx 0.693\). By Exercise 5, unmasked self-attention without positional information is permutation equivariant, and the FFN, residual connections, and LayerNorm all act on each token separately. Shuffling the 8 digit tokens therefore only shuffles their outputs, and the [CLS] output (which attends to all of them) does not change at all. The model only sees the multiset of digits. Any multiset of digits can appear both sorted (as a positive) and shuffled (as a negative), so the multiset carries essentially no information about the label. With position embeddings, each token knows where it is, and the task becomes easy.

def make_batch(batch_size):
    src = torch.randint(10, (batch_size, n))
    tgt = src.flip(dims=[1])                         # the reversed sequence
    bos = torch.full((batch_size, 1), BOS)
    eos = torch.full((batch_size, 1), EOS)
    tgt_in = torch.cat([bos, tgt], dim=1)            # <BOS> y1 ... yn   (shifted right)
    tgt_out = torch.cat([tgt, eos], dim=1)           # y1 ... yn <EOS>
    return src, tgt_in, tgt_out

All sequences here have the same length. Real seq2seq data has sequences of different lengths, which are padded to a common length; an extra padding mask then stops the attention from looking at the padding tokens, and decoding stops at <EOS>.

(d) Why can the encoder use unmasked self-attention, while the self-attention in the decoder must be masked? In cross-attention, which tensor provides the queries, and which provides the keys and values?

(a)-(b)

class DecoderBlock(nn.Module):
    def __init__(self, d_model, n_heads, d_ff):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, n_heads)
        self.cross_attn = MultiHeadAttention(d_model, n_heads)
        self.ffn = nn.Sequential(nn.Linear(d_model, d_ff), nn.ReLU(), nn.Linear(d_ff, d_model))
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.norm3 = nn.LayerNorm(d_model)

    def forward(self, s, z, mask):
        a = self.norm1(s + self.self_attn(s, s, mask))   # masked self-attention
        b = self.norm2(a + self.cross_attn(a, z))        # queries from a, keys/values from z
        return self.norm3(b + self.ffn(b))

class Seq2SeqTransformer(nn.Module):
    def __init__(self, vocab_size, max_len, d_model=64, n_heads=4, d_ff=128, n_layers=2):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_len, d_model)
        self.encoder = nn.ModuleList([Block(d_model, n_heads, d_ff) for _ in range(n_layers)])
        self.decoder = nn.ModuleList([DecoderBlock(d_model, n_heads, d_ff) for _ in range(n_layers)])
        self.out = nn.Linear(d_model, vocab_size)

    def embed(self, idx):
        return self.tok_emb(idx) + self.pos_emb(torch.arange(idx.shape[1]))

    def encode(self, src):
        z = self.embed(src)
        for block in self.encoder:
            z = block(z)                                 # no mask in the encoder
        return z

    def decode(self, tgt_in, z):
        s = self.embed(tgt_in)
        mask = causal_mask(tgt_in.shape[1])
        for block in self.decoder:
            s = block(s, z, mask)
        return self.out(s)                               # (B, m, vocab_size)

    def forward(self, src, tgt_in):
        return self.decode(tgt_in, self.encode(src))

    loss = F.cross_entropy(logits.reshape(-1, vocab_size), tgt_out.reshape(-1))
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 250 == 0 or step == 999:
        print(f"step {step:4d}  loss {loss.item():.4f}")

@torch.no_grad()
def greedy_decode(model, src, n_new=n + 1):
    z = model.encode(src)                                # encode the source once
    out = torch.full((src.shape[0], 1), BOS)
    for _ in range(n_new):
        next_tok = model.decode(out, z)[:, -1].argmax(dim=-1, keepdim=True)
        out = torch.cat([out, next_tok], dim=1)
    return out[:, 1:]                                    # drop <BOS>

src, _, tgt_out = make_batch(1000)
pred = greedy_decode(model, src)
print("exact match:", (pred == tgt_out).all(dim=1).float().mean().item())
print("input: ", src[0].tolist())
print("output:", pred[0].tolist())

(d) The encoder reads an input sequence that is entirely known in advance, so every input token can use context from both sides. The decoder is trained with teacher forcing to predict token \(i+1\) from tokens \(1, \dots, i\). Without the mask, it could read the answer from position \(i+1\) of its input (see Exercise 7(e)), and at generation time the future tokens don’t exist yet. In cross-attention, the queries come from the decoder (the output of its masked self-attention sublayer), and the keys and values come from the final encoder outputs \(Z\). This is how each output position looks up the relevant input tokens; for reversal, output position \(i\) learns to attend to input position \(n + 1 - i\).
